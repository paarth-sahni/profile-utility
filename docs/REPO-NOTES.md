# Repo Notes: InfoBeans Profile Generator

Updated 2026-10-22 (HEAD `081f6d5`). The first version of this file (2026-10-05) described the old static, browser-only
app; that app no longer exists. This is the current map. The [README](../README.md) has the how-to detail (PDF,
Google Docs, tests, manual checks); this file is the orientation.

## 1. Stack at a glance

| Thing | Value |
|---|---|
| Framework | Next.js 16 (App Router), React 19, TypeScript strict. Read `node_modules/next/dist/docs/` before changing framework-level code (see `AGENTS.md`) |
| Output | `output: "standalone"`: a Node server (not a static export) |
| Styling | Tailwind v4 tokens in `app/globals.css`, Lexend |
| Validation | `zod` 4 (`lib/schemas.ts` is the source of truth for the profile shape) |

| Documents | `docxtemplater` + `pizzip` fill the Word templates; **PDF** is made server-side by LibreOffice (`lib/pdfRender.ts`) |
| Database / auth | Supabase (Postgres + Auth, Google sign-in, `@infobeans.com` only), Row Level Security on every table |
| Tests | `npm test` (unit), `test:db`, `test:rls`, `test:render`, `test:e2e` (see README) |

## 2. What the app does

1. Sign in with Google (`/login`, `proxy.ts` guards the protected routes). A sign-in lasts at most 2 hours.
2. **Generator** (`/internal`, `/external`, shared `components/ProfileWorkflow.tsx`): Start -> Upload profile
   (`POST /api/extract`, LLM fills the form, `ExtractionSummary` asks the user to review everything) -> Edit details ->
   Preview (& Submit for internal). Preview shows the real PDF (`POST /api/pdf`); Download PDF needs the consent tick
   (`POST /api/consent` writes `audit_log`).
3. **Internal** profiles are saved only by Submit, as automatic versions (Base, v2, v3) under **My Profiles**
   (`/profiles`, `/profiles/[id]`). Each person has at most one **primary** profile. **External** profiles are never
   stored (`POST /api/profiles` answers 400 `EXTERNAL_NOT_SAVED`).
4. **ProfileHub** (`/manage`, managers and admins): one row per team member (their primary profile), name search,
   read-only profile page with Download PDF and Open in Google Docs.
5. Public pages: `/instructions` (per template), `/style-guide` (PDF embed, not linked from the header).

Roles: `team_member`, `checker`, `manager`, `admin`. Everyone creates/saves/submits their **own** profiles; checkers,
managers and admins can read everyone's (managers/admins through ProfileHub only). The role is read from
`public.app_users`, never from the JWT.

RPCs `save_profile_version`, `submit_profile_version`, `set_primary_profile`; search is `search_profiles_by_name`
(typo-tolerant, internal profiles only).

## 5. Things to know before changing code

- **Three-way contract**: the zod schema, the extraction prompt and the Word templates must change together
  (plus `docxData.ts`, the forms and the tests). A schema field with no template tag is silently dropped from the
  document.
- **Templates are generated**: never edit `public/templates/*.docx` by hand; change `scripts/patch-templates.py` and
  run it. Word splits `{tags}` across runs when retyped.
- **PDF needs LibreOffice** (`soffice` 7.3+) on the server and the Lexend fonts in `public/fonts`. Without it the API
  answers 503 `CONVERTER_MISSING`.
- **Rate limits are in memory** per server process: 10 extractions, 60 PDFs and 60 saves per 10 minutes per user.
- **Secrets**: `GROQ_API_KEY`, and for the client-name registry `GOOGLE_SA_PRIVATE_KEY`, `SYNC_CRON_SECRET` and
  `SUPABASE_SERVICE_ROLE_KEY`, only on the server. The service-role key is read in ONE file (`lib/sync/adminClient.ts`, enforced by a
  test) and `service_role` has no table access to the registry, only its functions; the platform still gives it full access to the
  rest of the database, so guard it like a root password. The production env file must not go into a bundle or git.
- **Sub-path hosting**: `NEXT_PUBLIC_BASE_PATH` is baked in at build time and read by hand in a few files that build
  URLs (`SiteNav`, `style-guide`, `lib/generate.ts`).
- **Known loose ends**: the database policies still let a manager read other members' non-primary rows (ProfileHub hides
  them in the data layer); `lib/templates.ts` and the starter SVGs in `public/` are unused; `public/templates/` still
  holds 12 old `.docx` files and a `.textClipping` besides `internal.docx` / `external.docx`, which ship with the
  build and are worth removing before go-live.
- `docs/tasks/TASK-01-auto-extract.md` and `TASK-02-database-roles.md` are the original briefs; both are implemented.
